# D1読み取り行数の確認（2026-09-08）

`3b3f3ab` と `0012_optimize_comment_and_recent_reads.sql` 適用後のコードを比較。
実際のAPI実装をTypeScriptから変換して一時D1のDrizzleへ接続し、生成されたSQLと
バインド値を取得。SQLを再実行して `meta.rows_read` と `EXPLAIN QUERY PLAN` を確認した。
本番DBには接続していない。ローカルMiniflare 4.20260508.0、compatibility date
2026-05-15での合成データによる測定で、本番のプラン・課金量を保証する値ではない。
キャッシュヒット時ではなく、SQLが実行される場合の値。

## コメントツリー

対象ページのルート20件と各10返信を取得（返却220件）。
同じページに古いルート1件とその返信1万件、別ページに10万件を追加し、
返却対象を変えずに読み取り行数の増加を調べた。

| データ                                     | 本体SQL・修正前 | 本体SQL・修正後 |
| ------------------------------------------ | --------------: | --------------: |
| 対象220件のみ                              |          48,080 |           1,340 |
| 対象220件＋別ページ10万件                  |         148,080 |           1,340 |
| さらに同じページの古いルート・返信10,001件 |       2,158,282 |           1,341 |

最後の条件で別途実行するルート件数集計は10,221行から22行へ減少。
`comments_reply_idx` により再帰探索の一時インデックス構築を解消。
`comments_roots_recent_idx` によりルートの取得・並べ替えで返信を走査しない。
継続判定の `EXISTS` は `CASE WHEN` で深さ上限の行だけ評価する。
返信先インデックスは削除済みも含め、参加スレッドの削除済み祖先を通る探索にも使う。

## その他のAPI

100ページ×100リビジョン（初回のみ通常編集、以降は軽微な編集）、
100ページに計1万コメントを配置。ユーザー1の投稿はルート1件、他の投稿はユーザー2。
最近の一覧は10件、返信は20件、履歴は50件を取得。
複数SQLのあるAPIは読み取り行数の合計。

| API                                                 |    修正前 | 修正後 |
| --------------------------------------------------- | --------: | -----: |
| 最近の編集（通常編集のみ）                          |    12,008 | 10,030 |
| 最近の編集（軽微な編集を含む）                      |    10,020 | 10,020 |
| 最近のコメント                                      |    20,800 | 10,593 |
| 直接返信                                            |    14,220 |    301 |
| 参加スレッドの返信                                  |    32,463 |    503 |
| コメント検索（全コメントに一致）                    | 2,021,928 | 20,040 |
| ページ履歴                                          |       100 |    100 |
| サイトマップ                                        |    20,000 | 20,000 |
| ページ検索（2文字のフォールバック、全ページに一致） |    40,400 | 40,400 |

- 最近の編集の表示順は既存の `pages_recent_*` を使用。新しい
  `pages_major_path_idx` と `pages_deleted_path_idx` で後続の通常編集・削除を直接検索する。
  この判定の条件は部分インデックスと一致するSQLリテラルにする。
- 最近のコメント・返信のページタイトルは主キーから最新リビジョンを1件参照し、
  全ページ履歴の `GROUP BY` と一時インデックス構築を廃止。
  最近のコメントは従来どおり最新の非削除リビジョン、返信は削除を含む最新リビジョンを参照する。
- 返信は `comments_user_recent_idx` から投稿者を絞り、`comments_reply_idx` で子を探す。
  `CROSS JOIN` で探索順を固定し、全コメントを日付順に読むプランを避ける。
- コメント検索は全履歴とのJOINを廃止。各コメントの最新ページを主キーで1件参照し、
  ページ履歴件数とコメント件数の積になる走査を解消。
- ページ履歴は `(path, revision)` 主キー、サイトマップの新リビジョン確認も同主キーを使用。

## 残る線形走査

以下はインデックス不足の多重走査とは異なり、集計・部分一致検索の仕様による。
今回の修正でも読み取り行数を定数にはできない。

- 最近の編集の正確な総件数は、全ページ履歴を集計する。このデータでは1万行。
- 最近のコメントはページごとの最大コメントIDを求めるため、非削除コメントの
  `comments_path_id_idx` 全体を走査する。
- コメントの `%term%` 検索と、ページの短い検索語のフォールバックは通常のB-treeで
  本文を絞り込めない。ページ検索の3文字以上は別のFTS経路を使う（今回の測定対象外）。
- サイトマップは全公開ページを列挙するため履歴の走査が残る。
- 深いOFFSETは読み飛ばす件数に比例し、削除・旧版の多い最近の一覧も候補走査が増える。
- 直接返信はそのユーザーの投稿・返信数に比例する。参加スレッドの探索には既存の
  種1000件・ルート500件・深さ100・ノード1万件の上限がある。

これらが負担になる規模では、最新ページ／最新コメントの集計テーブル、件数キャッシュの共有、
カーソルページング、コメント検索のFTS化を別途検討する。
書き込み時の同期・削除／復元・キャッシュ整合性が関わるため、今回のインデックス修正には含めない。
